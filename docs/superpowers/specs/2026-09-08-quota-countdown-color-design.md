# 额度重置倒计时与分级颜色设计

## 目标

在现有 Codex 额度悬浮窗中，为 5 小时额度和 7 天额度分别显示重置倒计时，并以清晰、统一的颜色标示各自的剩余比例。该功能只扩展展示层，不改变本机 Codex App Server 的读取方式、不增加登录或网络请求。

## 已确认交互

采用“信息分两行”版式：

- 每个额度项目的左侧第一行显示周期名称（`5小时`、`7天额度`）。
- 左侧第二行显示英数字倒计时和本地重置时间，例如 `2h 18m · 09/12 18:30` 或 `4d 12h · 09/12 18:30`。
- 右侧显示剩余百分比；百分比是唯一使用额度颜色的文字，倒计时保持低对比度浅灰，以保证扫读清晰。
- 每项额度下方增加约 200 x 2 px、1 px 圆角的细进度轨道；填充长度对应剩余百分比并沿用同一四色规则，无数据时仅显示灰色轨道。
- 窗口扩大为约 360 × 140 px；卡片高度约 132 px，顶部折叠时仍保留底部 8 px 的悬停区域。
- 右键“刷新”、自动收起、悬停展开、状态行和原有重试行为保持不变。

## 颜色规则

颜色只由剩余百分比决定，边界固定如下：

| 剩余比例 | 颜色 | 含义 |
| --- | --- | --- |
| 81–100% | 绿色 | 额度充足 |
| 50–80% | 黄色 | 开始关注 |
| 20–49% | 琥珀色 | 额度偏低 |
| 0–19% | 红色 | 接近耗尽 |
| 缺失 | 中性灰 | 未取得该额度 |

为确保黄色和琥珀色可分辨，使用两个不同色相：绿色 `#55D6A4`、黄色 `#F7DE6B`、琥珀色 `#F2B85D`、红色 `#FF7C74`、中性灰 `#D7DEE7`。

## 倒计时规则

`QuotaState` 已保存两个 `ResetAt` 时间戳，界面只需基于本地当前时间格式化，无需为倒计时发起新请求：

- 剩余至少 1 天：`Xd Yh · MM/dd HH:mm`。
- 剩余至少 1 小时：`Xh Ym · MM/dd HH:mm`。
- 剩余至少 1 分钟且不足 1 小时：`Ym · MM/dd HH:mm`。
- 剩余不足 1 分钟或时间已到：`<1m · MM/dd HH:mm`，等待下一次已有的额度读取刷新结果。
- `MM/dd HH:mm` 使用本地时间，作为具体重置日期和时间点；重置时间缺失仍显示 `--`。
- 重置时间缺失：显示 `--`。

新增一个一分钟的 UI 定时器，仅重绘倒计时文本；已有的一分钟额度刷新定时器继续通过 App Server 获取最新额度。读取失败时，百分比继续使用最后一次成功读数，倒计时仍按该读数的重置时间推进；若时间已到则显示 `即将重置`，不显示负数时间。

## 实现边界

- 在 `MainWindow.xaml` 调整卡片行高、窗口高度，并增加两个倒计时 `TextBlock`。
- 在 `MainWindow.xaml.cs` 增加倒计时 UI 定时器、文本格式化和额度颜色映射；释放窗口时一并停止及解绑该定时器。
- 不改动 `QuotaParser` 的协议读取逻辑，因为它已经解析并保留 `FiveHourResetAt` 与 `WeeklyResetAt`。
- 不增加配置、托盘、设置页、历史记录或外部服务。

## 验收

1. 有重置时间时，两项额度分别展示正确的非负倒计时，且无需额外调用 App Server。
2. 百分比分别在 81、80、50、49、20、19 等边界值显示正确颜色。
3. 缺失额度或重置时间时安全显示中性灰百分比或 `--`。
4. 现有刷新、失败保留、收起展开、右键菜单和退出清理仍正常工作。
