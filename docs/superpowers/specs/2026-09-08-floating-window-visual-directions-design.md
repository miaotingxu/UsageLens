# CodexQuotaFloat 悬浮窗视觉方案设计

## 目标

为当前额度与 Token 同屏悬浮窗制作四款可比较的 HTML 视觉原型，改善层级、密度与精致度。原型只用于选型，不修改 WPF 生产界面。

## 固定约束

- 保持 300 像素逻辑宽度，以当前 205 像素高度为基准；允许原型在不拥挤的前提下上下浮动少量高度。
- 四款方案均完整显示：5 小时剩余额度、5 小时重置倒计时与时间点、进度条、7 天剩余额度、7 天重置倒计时与时间点、进度条、当日 Token 与价格、近 7 天 Token 与价格、近 30 天 Token 与价格、额度更新时间和 Token 更新时间。
- 保持 70% 不透明的悬浮卡片语义、80×8 折叠把手、四色额度规则、Token 蓝色、价格绿色。
- 不增加页面切换，不减少数据，不改变自动折叠、置顶、刷新和右键菜单行为。
- 原型使用同一组示例数据，便于横向比较。

## 四个方向

### A. 精密仪表

工业仪表风格。额度区域采用小型环形刻度与百分比组合，重置时间位于刻度右侧；Token 数据使用紧凑读数条。优点是状态感强，缺点是 WPF 实现成本较高。

### B. 双层玻璃（推荐）

深色双层玻璃卡片。上层以两张并列小卡展示额度，下层用三行表格展示 Token。信息区域边界明确，扫描路径最自然，适合长期悬浮阅读，也最容易在 WPF 中稳定还原。

### C. 横向时间轴

将两条额度进度做成横向时间轴，百分比位于轨道末端，重置时间作为时间轴注释；Token 作为底部统计带。优点是进度感最直观，缺点是长重置时间更考验宽度。

### D. 极简终端

专业工具风格。使用等宽数字、细分隔线和低饱和底色，颜色只标记百分比、Token 和价格。信息密度最高、最克制，但视觉亲和力较弱。

## 原型交互

- 页面将四款方案并排展示，并提供顶部方案按钮以聚焦单款。
- 每款卡片支持“展开 / 折叠”演示；折叠后只显示 80×8 把手。
- 不接入真实数据，不修改应用代码，不模拟不存在的设置功能。

## 选型标准

- 所有字段在默认缩放下清晰可读且没有截断。
- 用户能在三秒内区分额度区与 Token 区。
- 关键数字优先于说明文字，状态信息不抢占视觉焦点。
- 方案能够用 WPF 原生布局、渐变、边框和基础几何图形可靠实现。

## 交付边界

本轮交付为一个本地 HTML 视觉对比页。用户选定其中一款后，再单独制定 WPF 实施计划并修改 `develop` 分支。
